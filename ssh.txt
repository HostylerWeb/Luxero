Luxero — SSH access to the three servers
============================================
This machine: use the Hostyler private key at ~/.ssh/id_ed25519 (mode 600).
Login user on all servers: root
Port: 22 (default)

IMPORTANT
---------
- Do not commit id_ed25519 or root passwords to git.
- The key must stay only on your laptop (~/.ssh/id_ed25519).
- If a key was ever pasted in chat or email, rotate it on the servers later.

Hostinger — move data (not DNS alone; Mongo alone is not enough)
-----------------------------------------------------------------
Two separate stores on Hetzner today:

  1) MongoDB — users, orders, competitions, settings, and image URL strings in documents
  2) SeaweedFS bucket luxero-assets — actual files (uploads/, prizes/, avatars/, frames/, etc.)

Admin Media library lists bucket objects via S3 API — not a Mongo "gallery" table.
Importing prod Mongo locally without copying MinIO → local gallery looks empty; that is expected.

Where images actually load from (three different things)
--------------------------------------------------------
  A) S3 bucket — binary files. Apps read/write via S3_ENDPOINT + credentials.
  B) ASSET_BASE_URL (and NEXT_PUBLIC_ASSET_BASE_URL on client/shop/lander) — base URL the
     API uses when it builds NEW public links after upload.
  C) Strings already saved in Mongo — often full https://assets.luxero.win/luxero-assets/…
     on competitions, products, settings. The browser requests those URLs as-is.

After mongorestore only: (B) and bucket may be local, but (C) still points at live Hetzner CDN.
That is why competitions can show images while /media looks empty until you sync the bucket.

Origin policy — CSRF, CORS, CSP (why Hostinger broke saves / images)
---------------------------------------------------------------------
Code (single source of truth): packages/env/src/origin-policy.ts
  Re-export for API paths: packages/api/server/src/lib/allowed-origins.ts → @luxero/env/origin-policy

What it controls:
  1) CSRF middleware (packages/api/server/src/middleware/csrf.ts)
     — Browser sends Origin on POST/PUT/PATCH/DELETE. If the origin is not allowed, API returns
       403 {"message":"Origin not allowed"} (e.g. admin Media Converter save).
  2) CORS (client bootstrap, apps/admin/app/api/[[...route]]/route.ts, shop API route)
     — Same allowlist via resolveCorsOrigin().
  3) CSP on HTML responses (client bootstrap.ts, apps/admin/next.config.ts headers)
     — img-src / media-src / connect-src must include your public asset host or images load with
       naturalWidth 0 even when curl to the asset URL returns 200.
  4) Better Auth trusted origins (packages/auth/admin/src/trusted-origins.ts)
     — Session cookies and auth callbacks for the deployed hostnames.

How allowlist is built (do not hardcode hosts in random files):
  • DEFAULT_ORIGIN_HOST_SUFFIXES — luxero.win, hstgr.cloud (edit in origin-policy.ts)
  • Optional env: ORIGIN_ALLOW_HOST_SUFFIXES=other.com,other.net
  • URL env vars listed in DEPLOYMENT_ORIGIN_ENV_KEYS (APP_URL, ADMIN_URL, SHOP_URL,
    S3_ENDPOINT, ASSET_BASE_URL, NEXT_PUBLIC_*, etc.) → exact origins for CSP/CSRF
  • Optional env: AUTH_TRUSTED_ORIGINS_EXTRA=https://extra.origin,https://other.origin

Hostinger checklist after changing hostnames or env:
  1) Regenerate or edit /root/luxero-*.env so APP_URL / ASSET_BASE_URL match the phase URLs.
  2) Rebuild Docker images (env is baked into Next at build for NEXT_PUBLIC_*).
  3) Smoke tests:
       curl -s -X PUT -H 'Origin: https://admin.srv2011364.hstgr.cloud' -H 'Content-Type: application/json' \
         -d '{}' https://admin.srv2011364.hstgr.cloud/api/admin/media-converter-settings

  4) If Mongo still has https://assets.luxero.win/... strings, run deploy/scripts/migrate-asset-urls.js

Method 2 — sshpass (only if key login fails and you have the root password)
---------------------------------------------------------------------------
sshpass sends the root password over SSH when the server allows password auth.
Install: sudo apt install sshpass   (already present on this laptop: /usr/bin/sshpass)

Prefer environment variable (password not stored in shell history):

  export SSHPASS='your-root-password-here'
  sshpass -e ssh -o StrictHostKeyChecking=accept-new root@167.233.52.87
  sshpass -e ssh -o StrictHostKeyChecking=accept-new root@95.216.158.37
  sshpass -e ssh -o StrictHostKeyChecking=accept-new root@187.7.28.125
  unset SSHPASS

Run one command without keeping password in env (less safe; shows in process list briefly):

  sshpass -p 'your-root-password-here' ssh root@167.233.52.87

Hostinger root password: use the value from Hostinger panel / password manager (not in this repo).
Hetzner servers may be key-only; sshpass only works if password login is enabled.

-----------------------------------------------------
After reinstall or rescue, remove old host keys then connect again:

  ssh-keygen -f ~/.ssh/known_hosts -R 167.233.52.87
  ssh-keygen -f ~/.ssh/known_hosts -R 95.216.158.37
  ssh-keygen -f ~/.ssh/known_hosts -R 187.7.28.125


Troubleshooting
---------------
- Permission denied (publickey,password): wrong or missing ~/.ssh/id_ed25519, or wrong permissions (must be 600).
- Connection timed out: firewall, wrong IP, or server down.
- Key works from this laptop after Dec 2025 setup; use Method 1 first, Method 2 only as fallback.

1. Summary

Luxero.win is a full competition business: customers enter online, pay by card, and staff run draws and admin from a separate login area. There is also a shop. The build is advanced, but our review found security holes, login/admin mismatches, website gaps, and missing marketing tools that should be fixed before you treat the site as fully live.

What Hostyler will do: work through everything the audits found - urgent staff-login fixes first, then all remaining technical issues and every security vulnerability we identified on Luxero.win, staff admin, payments, and customer data.

We will tidy data and payments, set up server housekeeping (caching and timed tasks) for fast loading and strong performance under traffic, and improve selected UI and UX so the site and admin feel polished and easy to use. We will install Facebook Pixel, Google Analytics, and Klaviyo so you can advertise and email properly, and keep your existing Umami stats.

Before go-live we will test the full platform from A to Z on staging - website, shop, checkout, staff tools, draws, and marketing tags - so Luxero.win launches with premium security, high performance, and as few bugs as possible. Hostyler aims to finish all five phases within 10 business days of project start. Details are in section 12.

4. Urgent issues (fix first)

IssueWhy it mattersWhat we will do
Staff admin access out of sync When you give or remove admin access in the panel, the login account may not update. Someone could keep admin powers after you removed them, or the opposite. Fix the link between the customer record and the login account; test grant and revoke; check live data.
Passwords in server logs Sign-in details may be written to log files where support staff or hosting tools can see them. Stop logging passwords; only log safely in development if needed.
Public data on staff server Some customer competition data is reachable on the staff website address without logging in as staff. Lock it down so only staff tools use the staff site.
Test passwords in code Automated tests contain example staff passwords. If those match real accounts, that is dangerous. Remove from code; change any matching real passwords.
Database not locked on dev servers Developer setups may use a database with no password. That must never be exposed on the internet. Passwords and locks on all live databases.

5. Other important issues

5.1 Staff admin and backend

  • Login security is too loose in places (website address checks, setup page visible, one emergency key used for too many things).
  • Some admin tools need repair (Google Sheets link for draws, large exports that can slow the system).
  • Bulk changes to who is admin should leave the same paper trail as changing one person.

5.2 Website (Luxero.win)

  • Contact form can be spammed; protection turns off if the speed helper service is down.
  • Some referral and deep links may not work yet on the website.
  • Public entry lists can be overloaded by bots searching names.

5.3 Database and records

  • Customer details exist in two places that must always match (profile and login).
  • Old orders may be deleted automatically after 90 days - you must confirm that fits your legal and accounting needs.
  • Some deleted records might still show in reports if queries are not careful.

5.4 Card payments (Paytriot today)

  • Card checkout on the main website is largely working (including 3D Secure and ticket delivery).
  • Refunds are done manually in Paytriot's merchant system, not by a button in your admin today.
  • We have a written process if payment succeeds but tickets fail to issue.
  • Switching provider: if Luxero prefers a different card payment company instead of Paytriot, Hostyler will connect that provider and make checkout work on Luxero.win. This is included in the quoted price - not an extra Hostyler fee (you still pay the new provider's own charges).

7. Keeping the site fast and running on time

7.1 Redis (speed and abuse protection)

A small helper service stores short-lived copies of popular pages and counts how often someone tries to log in or pay. That keeps Luxero.win quick under load and reduces spam. Live hosting should always include it.

We will: set it up on production, document it for your host, and make sure limits still work if the helper service has a hiccup.

7.2 Scheduled tasks (like cron jobs)

Some jobs must run on a timetable: checking competitions ready to draw, sending scheduled notifications, cleaning old orders, bonus prizes, and health checks. These are triggered by secure web calls from your hosting scheduler (not a visible button for the public).

We will: document what to schedule, use separate secrets for staff recovery vs automated jobs, and avoid duplicate runs when you have more than one server.

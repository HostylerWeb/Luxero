Luxero — what was fixed
=========================
Branch: dell-laptop (work from this machine; do not merge to main without review)

Format: Area: It was doing X, now it does Y, we fixed it because Z.


--- Already on GitHub (main, audit Pass 3–5 + platform work) ---

Checkout / cart / promos: It was allowing invalid promos, wrong caps, and racey cart state; now it validates promos against the user, respects sales windows, and aligns cart with Pass 4–5 tracker items; we fixed it because customers could checkout incorrectly or abuse discounts.

Payment gates (Stripe / local / card block): It was missing provider checks and local bypass in prod paths; now local payments and card methods are gated by env and admin settings; we fixed it because money could flow through the wrong provider in the wrong environment.

Compliance / auth hardening (Pass 4–5): It was weaker on guest checkout and verification edges; now tracker-marked compliance items are implemented; we fixed it because gambling/compliance rules require enforced limits.

Admin role sync: It was updating Profile but not Better Auth user.role; now admin PATCH/bulk use updateAuthUserFields; we fixed it because managers/admins could look correct in UI but still have old session roles.

Stripe integration: It was absent in the old snapshot; now Stripe provider, webhooks (verified), and UI exist on main; we fixed it because the product moved off Paytriot-only.

Deploy / local docs: It had outdated README-only setup; now deploy/ and docs/local-development.md exist; we fixed it because handoff and Coolify deploy needed a single source of truth.

Instant prizes / admin UX: It had rough admin flows; now instant-prize and nav improvements from Oct 2026 commits; we fixed it because ops needed safer prize assignment.


--- Fixed on this machine (dell-laptop — security & hardening pass) ---

Paytriot fulfillment: It was accepting responseCode=0 without valid signature or amount check; now it requires signature (unless PAYTRIOT_LENIENT_RESPONSE_SIGNATURE=true) and matching amountReceived; we fixed it because anyone could POST fake success and get tickets.

Profile-fill API: It was looking up any email and returning PII; now it only loads the signed-in user’s profile by userId; we fixed it because anonymous sessions could harvest addresses/phone/DOB.

Public entries search: It was passing raw regex and lastName search; now search is escaped, length-capped, and lastName is not searchable publicly; we fixed it because ReDoS and hidden surname probing were possible.

Public entries pagination (H3): It was accepting arbitrary sortField and cursor JSON fields; now only entryNumber/createdAt sort and cursors must be { entryNumber, _id } with valid types; we fixed it because attackers could inject aggregation sort keys and read private fields.

Public winners list: It was returning full Winner documents and email-based names; now it returns a minimal public shape (displayName, prize, ticket, drawnAt, competition title/slug/image only); we fixed it because PII and internal fields leaked on a public API.

Public winners by competition: It was populating user profiles; now it returns the same minimal public fields from stored displayName; we fixed it because the endpoint exposed firstName/lastName/avatar.

Admin setup/emergency UI: It was embedding NEXT_PUBLIC_* secrets in the JS bundle; now secrets are typed manually and .env.example forbids NEXT_PUBLIC copies; we fixed it because anyone could read emergency/setup secrets from static assets.

Internal cron jobs (C2): It was using the same header secret as emergency recovery; now /api/internal/jobs requires X-Cron-Jobs-Secret + CRON_JOBS_SECRET (separate from ADMIN_EMERGENCY_SECRET); we fixed it because leaking one secret triggered all jobs and OTP flows.

CSRF middleware (C6): It only blocked obvious cross-site Origin; now it blocks Sec-Fetch-Site cross-site/none, validates Origin allowlist, and requires same-site Origin or X-Luxero-Client: 1 when Origin is missing; we fixed it because cookie-authenticated POSTs from other sites could mutate state. (SameSite=None cookies unchanged — still rely on Origin checks + CSP.)

Browser API client: It was not identifying same-app requests; now axios sends X-Luxero-Client: 1; we fixed it because CSRF middleware needs a trusted marker for same-origin fetches without Origin.

Rate limits: Admin/shop APIs lacked client rate limits; payment/discount validate were unthrottled; IP used spoofable X-Forwarded-For; now email/payment limits on admin/shop, discount paths throttled, IP from cf-connecting-ip/x-real-ip only; we fixed it because brute force and scraping were easier.

Manager RBAC: Hono /:id middleware did not cover sub-routes; now /:id and /:id/* require admin for competition/winner writes (except end-draw); we fixed it because managers could restore/undraw/claim via nested paths.

Admin global search: It had no query bounds or timeouts and wrong detail URLs; now min 2 / max 100 chars, 5s aggregate cap, ticket number matched first, URLs fixed; we fixed it because one keystroke could scan whole collections and hang Mongo.

Balance ledger TTL: It was deleting all transactions after 90 days; now TTL applies only to pending/failed and idempotency is per userId+key; we fixed it because completed wallet history must not auto-delete.

Affiliate postbacks: It allowed literal IPs and redirect SSRF; now hostnames only, stricter private ranges, fetch redirect disabled; we fixed it because admin-configured URLs could hit internal services.

Shop Paytriot form: It returned any shop order’s form HTML by id; now scoped to session userId; we fixed it because IDOR leaked signed payment forms.

Order fulfillment transactions: It could silently retry without a Mongo transaction; now finalize uses strictOnTxFailure; we fixed it because ticket allocation could double-run on transient errors.

Payments health: It called Stripe/Paytriot on every anonymous GET; now requires session and prod returns static ok; we fixed it because it was a DoS/Stripe rate-limit amplifier.

Mobile app: Referral /r/:code was unwired and dashboard/checkout had no guards; now route exists and RequireAccount wraps dashboard/cart/checkout; we fixed it because the Capacitor app did not match web auth boundaries.

CSP / clickjacking: Admin/shop/lander had weak framing rules; now frame-ancestors none + X-Frame-Options on pages; admin debug console hook is dev-only; we fixed it because admin UI could be embedded in malicious iframes.

Setup secret: It accepted setup with no SETUP_SECRET in prod; now prod requires SETUP_SECRET; we fixed it because open setup could create admin on a fresh DB.

Secret comparison: It used === for timing-sensitive secrets; now secretsEqual uses timingSafeEqual; we fixed it because naive compare leaks guess timing.

Auth rate limit: Better Auth limit was off unless env set; now defaults on in production; we fixed it because login/OTP could be hammered.

Docker dev MinIO: Quay images 401 on this host; now uses docker.io minio images in docker-compose.dev.yml; we fixed it because local infra would not start.

.gitignore: PDFs could be committed; now *.pdf ignored; we fixed it because proposal PDFs must not go to GitHub.


--- VPS / production ops (do after deploy) ---

1. Rotate secrets if NEXT_PUBLIC_SETUP_SECRET or NEXT_PUBLIC_EMERGENCY_SECRET ever existed in a built admin bundle: new SETUP_SECRET, ADMIN_EMERGENCY_SECRET, BETTER_AUTH_SECRET, and a new CRON_JOBS_SECRET (never reuse emergency secret for cron).

2. Set CRON_JOBS_SECRET in admin/API env. Schedule cron POSTs to https://<admin>/api/internal/jobs/<job-name> with header X-Cron-Jobs-Secret: <value> (not X-Emergency-Secret). Example jobs: check-competitions-for-draw, cleanup-abandoned-orders, process-scheduled-notifications, check-bonus-awards, retry-order-confirmation-emails, ticketing-anomaly-checks.

3. Drop old Mongo TTL on balance_transactions if prod already created the global 90-day index (run dropIndex once, then deploy new partial TTL):
   mongosh "$DATABASE_URL" --eval 'db.balance_transactions.dropIndex("createdAt_1")'
   Then restart app so Mongoose ensures the new partial TTL index (pending/failed only).

4. Paytriot: Test checkout in staging with strict signatures. Only set PAYTRIOT_LENIENT_RESPONSE_SIGNATURE=true if Paytriot hosted responses fail signature verification and support confirms.

5. Confirm Redis is up in prod (rate limits and some checkout paths fail closed without Redis).

6. Review Order TTL (90d on completed/refunded) with finance before go-live; unchanged in code.

7. Remove or gitignore root sys (~24MB junk) if still present locally before any future push from another machine.
